# iPhone 方向盘：真机使用步骤

> 用户在真机上试过一次（Wi-Fi），反馈"连接不太稳定"。之后这一轮改了连接（有线、UDP 通道、断流处理、连接数字显示），**这些改动都还没在真 iPhone 上试过**，只用无头 Chrome 加模拟的传感器、触摸和网络故障测过（`scripts/phone-e2e.ts`、`scripts/phone-netsim.ts`）。有线连接只验证到"出现 iPhone USB 网卡时服务、证书、二维码都对"。

## 下次试的时候请看这 5 件事
1. **先试有线**（见下面"有线连接"）：配对面板里有没有出现"有线 · iPhone USB"那一项，扫它的码能不能打开、能不能开起来。
2. **看数字**：游戏右上角的小字（`手机 UDP 12/30 ms · 60 Hz · 5 s 断流 0`）和手机仪表下面两行小字。告诉我：通道是 UDP、WS 还是 POST，往返两个数（中位 / p95），断流次数。有线和 Wi-Fi 各开一段，各报一次。
3. **卡的时候**：游戏里有没有弹"手机信号中断 0.x s"，大概多久一次；手机仪表上是否出现"信号中断…"。没弹提示但手感卡，也请告诉我（那就不是网络的问题）。
4. **一局结束后按 K**：配对面板最下面"上一局"那行（断流次数、最长一次、卡顿、丢包、往返、各通道占比）拍照发我。
5. **锁屏 / 切出去再回来**：不用重新扫码、1 秒左右自己恢复吗；玩 5 分钟屏幕会不会自己熄灭。

## 启动
```
./play.sh            # 开发版，游戏在 http://localhost:5198，手机页在 https://<Mac 的地址>:6198/pad
./play-stable.sh     # 稳定版（尘迹拉力.app 也是它），http://localhost:5199，手机页在 :6199
```
- 游戏里按 **K**（或 URL 加 `pair=1`）弹出配对面板：每个可用地址一个标签（Wi-Fi、有线、以太网……）、二维码、步骤、连接状态和连接数字。再按 K 或 Esc 关闭。
- 双击 `尘迹拉力.app` 等于 `./play-stable.sh`，同样带手机服务。
- 端口上已经有一个 DUSTMARK 服务在跑同一个版本时，脚本直接用它（再开一个窗口也行）。端口被别的程序占着时，脚本会说明情况并自动换下一个端口（开发版 5197…5194，稳定版 5193…5191），手机页端口跟着变成"游戏端口 + 1000"，二维码里的地址也会跟着变；它不会去关掉不认识的进程。
- `npm run dev` 启动的游戏不支持手机方向盘，配对面板会提示改用 `./play.sh`。
- **更新后请重启一次游戏**：正在运行的旧服务不认识有线网卡，而且插线时会把旧证书重签（已配对的手机又要点一次证书警告）。新服务不会再改旧证书。

## 有线连接（推荐）
数据线直连，不经过路由器，没有 Wi-Fi 的干扰、漫游和 AP 隔离。不用装 App。
1. iPhone 用数据线（USB-C 或 Lightning）接到 Mac。第一次接时 iPhone 会问"要信任此电脑吗"，点**信任**。
2. iPhone 打开 **设置 › 个人热点 › 允许其他人加入**。Mac 上会多出一个叫 **iPhone USB** 的网络（地址一般是 `172.20.10.x`，手机自己是 `172.20.10.1`）。
3. 游戏里按 **K**。几秒内配对面板会多出 **"有线 · iPhone USB（推荐）"** 标签并自动选中（不用重启游戏，面板开着也会自己切过去）。
4. 用 iPhone 相机扫码。这是一个新地址，证书警告要再点一次 **显示详细信息 → 访问此网站**。之后照常点"开始"。

**风险：Mac 可能改用手机流量上网。** 个人热点打开后，Mac 会把 iPhone USB 当成一条可以上网的线路；它排在 Wi-Fi 前面时，Mac 的所有上网流量都走手机的蜂窝数据（下载、更新、同步都会算流量）。
- **怎么看**：系统设置 › 网络，列表最上面、标着"已连接"的第一项就是 Mac 现在上网用的那条。也可以在终端里运行 `route -n get default | grep interface`，显示的网卡名和面板上有线标签里的网卡名（例如 `en9`）一样，就是在走手机流量。
- **怎么避免**：系统设置 › 网络 › 列表下面的 **"…"** › **设定服务顺序…**，把 **Wi-Fi 拖到 iPhone USB 上面**，点好。这样 Mac 上网仍然走 Wi-Fi，只有游戏和手机之间的数据走线。这个设置只需要做一次。游戏不会去改你的网络设置。
- 个人热点那一页没有开关、或者提示要联系运营商：说明这张卡的套餐不支持个人热点，有线这条走不通，只能用 Wi-Fi。
- 玩完可以关掉个人热点再拔线。

## 蓝牙
- **蓝牙直连做不到**：iPhone 上的 Safari 没有 Web Bluetooth，网页拿不到蓝牙。要做得写一个原生 iOS App 当蓝牙手柄，不在这个项目的范围里。
- **蓝牙个人热点能连，但不推荐**：Mac 通过蓝牙加入 iPhone 的个人热点后，面板里会出现"蓝牙热点（慢，不推荐）"标签。蓝牙的带宽小、延迟和抖动都比 Wi-Fi 大，能用但不会比 Wi-Fi 稳。要稳就用有线。

## 第一次连接（Wi-Fi）
1. 手机和 Mac 连**同一个 Wi-Fi**。
2. 用 iPhone **相机**扫配对面板上的二维码（选 Wi-Fi 标签），在 Safari 中打开。
3. 出现「此连接非私人连接」：点**显示详细信息** → **访问此网站**，再确认一次。证书是服务第一次用到这个地址时在 `~/.dustmark/` 里自己生成的，只在这台 Mac 上用，没有装到系统里。每个地址一张证书，生成后不再改：家里、公司、有线各点一次就行，换回来不用再点。
4. 点**开始**，在「动作与方向」询问里点**允许**。
5. 横握手机，像握方向盘一样。先把手机端平，按一下**回中**。

如果 Mac 打开了防火墙，第一次启动时可能弹「是否允许 node 接受传入连接」，要点**允许**，否则手机连不上。

## 操作
- **转向**：转动手机（绕屏幕中心旋转）。默认 ±60° 满舵，设置里可以调 30–90°，也能调死区和曲线。左手横握、右手横握都可以。
- **回中**：把当前角度设为正中。方向盘图标和下面的横条能看出现在给的转向量。
- **油门 / 刹车**：右半屏是油门，左半屏是刹车。按下就是 60%，手指往上滑到 100%，往下滑到 20%。设置里可以改成「开关」（按下即 100%）。
- **手刹**：左下的红色大按钮（按住生效）。**降挡 / 升挡**在左上和右上角。
- 顶部的小按钮依次是暂停、切视角、P 轨迹预测、回到赛道（罚 5 秒），最后是设置。手机上的"暂停"能暂停，但继续要在 Mac 上按 Esc 或点"继续"（暂停菜单不收手机的输入）。
- 手机端得**立着**握。往后仰到接近平放时转角算不准，屏幕上会提示「请把手机立起来一点」，这时转向自动回中。
- 竖屏时会盖一层「请横握手机」。如果横过来画面不转，到控制中心关掉竖排方向锁定。

## 连接数字怎么看
手机仪表下面两行（每秒刷新 4 次）：
```
UDP 12/30 · WS 15/42 ms          ← 各通道往返时间：中位 / p95（最近 5 秒）
发 60 Hz · 游戏收 59 Hz · 5 秒断流 0 · 丢 0.0%
```
游戏右上角：`手机 UDP 12/30 ms · 60 Hz · 5 s 断流 0`（通道、往返中位 / p95、游戏每秒收到的新包、最近 5 秒断流次数；丢包 ≥ 0.5% 时再加一项）。配对面板（K）里有完整的一份，外加"本局"和"上一局"的统计。

| 数字 | 正常 | 有问题 |
|---|---|---|
| 通道 | UDP（最好）或 WS | POST = 备用通道，WebSocket 和 UDP 都没通，延迟和卡顿都会大一些 |
| 往返中位 | 有线 < 10 ms，Wi-Fi < 25 ms | > 50 ms |
| 往返 p95 | < 2 × 中位 | 比中位大很多 = 抖动大，会一卡一卡 |
| 手机发 / 游戏收 | 都在 60 左右 | 发 60、收明显少 = 路上丢；发也少 = 手机降频（低电量模式、过热） |
| 断流（> 150 ms 没收到） | 0 | 每分钟好几次 |
| 卡顿（> 50 ms 没收到） | 偶尔 | 一直在涨 |

## 断线和断流
- **短断流**（< 0.15 s）：游戏保持手机最后一帧的输入，感觉不到。
- **更长**：转向在 0.3 s 内匀速回到中间，油门、刹车、手刹在 0.08 s 内松开（不会自动踩刹车）；信号回来后 0.1 s 内平滑接上新的输入，不会一下跳过去。中断超过 0.25 s，游戏右上角弹一下"手机信号中断 0.4 s"（黄色，2 秒后消失）。
- **超过 0.5 s**：手机不再提供输入（键盘、手柄照常可用），右上角显示红色的「手机断开 · 已收油回中 · 按 K 查看」，回来后显示"手机已连接 · 中断了 x.x s"。
- 手机锁屏、切到别的 App 再回来，页面会自己重连（不用重新扫码，配对码存在手机里）。连接还活着就直接接着用；系统把连接关了就马上重建，在电脑上一般 0.1 秒内恢复，Wi-Fi 上要多一两个来回。手机上只有 2 秒以上完全收不到东西才会盖上「连接断开」，之前只在顶上显示"信号中断 x.x s…"，按着的油门不会因此松掉。
- 只有 `play.sh` 重启过才需要重新扫码，手机会提示「配对码已失效」。
- 同时只能连一台手机。第二台连上后，第一台会显示「另一台手机接管了方向盘」；在那台上点"刷新"可以再抢回来。

## 常见问题
| 现象 | 处理 |
|---|---|
| 扫码后打不开 / 一直转圈 | 确认手机和 Mac 在同一个 Wi-Fi。公司、学校、酒店的 Wi-Fi 常开「AP 隔离」，设备之间互相访问不了：改用**有线**。配对面板上的 VPN / 虚拟网卡标签（灰色）一般连不上，别选它。 |
| 面板里没有"有线"标签 | iPhone 的个人热点没打开，或者没点"信任此电脑"。打开后等几秒，面板会自己出现这一项。 |
| 插上线以后 Mac 上网变慢 / 手机流量在跑 | 见"有线连接"里的"设定服务顺序"。 |
| 防火墙弹窗 | 点「允许」。点错了就到 系统设置 › 网络 › 防火墙 › 选项 里把 node 改成允许。 |
| 没有弹出「动作与方向」询问，或之前点了不允许 | 关掉这个标签页，再从二维码重新打开。还不行就彻底退出 Safari 再试，或者到 设置 › App › Safari › 高级 › 网站数据 里删掉这个地址的数据。 |
| 转向反了 | 手机页「设置」里勾上「转向反向」。 |
| 一直显示「没有收到陀螺仪数据」 | 权限没给，或者地址不是 `https://` 开头。 |
| 一卡一卡 / 延迟大 | 看上面"连接数字"那张表。Wi-Fi 上就换有线；通道是 POST 时请告诉我。 |
| 屏幕自己熄灭 | 关掉低电量模式；或者把 设置 › 显示与亮度 › 自动锁定 改成「永不」，玩完再改回来。手机页下方出现「屏幕可能会自动锁定」说明两种防息屏办法都没生效。 |
| 页面能缩放、会回弹 | 不应该出现。如果出现了请截图告诉我。 |

## 技术细节（给开发者）
- **服务**：`scripts/serve.mjs`（纯 Node，`play.sh` / `play-stable.sh` 通过 `scripts/launch.sh` 用 `node` 启动；`/pair-info` 里的 `server: "dustmark-serve"` 和 `dir` 用来认出自己的服务）。`http://localhost:<port>` 提供游戏和 `GET /pair-info`，只对本机开放。`https://<地址>:<port+1000>/pad` 提供手机页。WebSocket 中继在 `/ws` 上，游戏用 `role=game`，手机用 `role=pad&k=<配对码>&sid=<会话>`。HTTPS 备用通道是 `POST /pad/io`。
- **网卡**（`scripts/serve-net.mjs`）：每 2 秒枚举一次本机私有 IPv4（10/8、172.16/12、192.168/16，不碰 Tailscale 等 100.x），用 `networksetup -listallhardwareports` 认出 Wi-Fi、iPhone USB、以太网、蓝牙 PAN，`utun*`/`ipsec*`/`ppp*`/`bridge100+` 等标成虚拟网卡（列出但从不默认选中）。默认选择顺序：iPhone USB → 默认路由所在的物理网卡 → 其他 Wi-Fi / 以太网 → 蓝牙 → 其他 → 虚拟。`/pair-info` 的 `addrs[]` 带 `kind / label / iface / listening`，`default` 是推荐地址。网卡出现就监听、消失就停，监听失败的地址 10 秒重试一次。
- **证书**：每个地址一张自签证书 `~/.dustmark/pad-ip-<地址>-{cert,key}.pem`（EC P-256，365 天，SAN = localhost、127.0.0.1、该地址），写一次就不再改，快过期（< 14 天）才换新的。旧版本的共用证书 `pad-cert.pem` 只读：它覆盖的地址继续用它（已经点过证书警告的手机不用再点），程序不会再写它。地址是 IP，TLS 没有 SNI，按"手机连的是哪个监听地址"选证书。
- **通道**：手机每个输入包同时走所有开着的通道——WebRTC 数据通道（`ordered:false, maxRetransmits:0`，丢了就丢，16 ms 后下一包顶上）和中继（WebSocket；WebSocket 不通时 POST）。游戏按 (ts, q) 只认最新的，重复和更旧的直接丢。WebRTC 没有任何 STUN / TURN（`iceServers: []`），只用本机候选；iOS Safari 和 Chrome 都把本机地址藏成 `xxxx.local` 的 mDNS 名，中继在每个 mDNS 候选旁边补一条用它实际看到的局域网地址的候选，组播被路由器挡住时也能连。6 秒没建起来就关掉，10 s、20 s……60 s 后再试，期间全部走中继。URL 加 `rtc=0` 关掉 UDP，`transport=http` 强制走 POST（测试用）。
- **WebSocket**：服务端关 Nagle（`setNoDelay`）、不压缩；每个输入包立刻回一个 `{t:'k',q}`，手机用它算每个包的往返时间，同时让手机的 TCP ACK 搭在数据上回去（不等延迟确认）。服务端每秒 ping，5 秒完全没动静才断开；断开后给 2 秒宽限期等手机重连（重连后游戏不重置状态，UDP 通道也不拆）。手机这边：WebSocket 开着但 0.8 s 没收到任何东西就换一条新的；没连上过的地址先走 POST，后台每 1 / 10 / 30 s 再试 WebSocket，连上就切回来（记在手机的 localStorage 里）。
- **发送**：固定 60 Hz 定时发（不跟 devicemotion 的节奏走），新的陀螺仪读数距上一包 ≥ 12 ms 就立即发，触摸变化 ≥ 8 ms 就立即发。
- **游戏端断流处理**（`PadHold`，`pad/padcore.js`）：`HOLD_MS = 150`、`FADE_MS = 300`、`RELEASE_MS = 80`、`RECOVER_MS = 100`、`PAD_TIMEOUT_MS = 500`；统计阈值卡顿 `STALL_MS = 50`、断流 `GAP_MS = 150`；比近 5 秒最快的包晚 `STALE_MS = 400` 以上才到的包当过期丢掉（TCP 积压放出来的旧输入）；HUD 提示阈值 250 ms（`phonePad.ts`）。
- **防息屏**：先用 Screen Wake Lock（Safari ≥ 16.4）；不支持或被拒时播放一段 1 KB 的 16×16 静音循环视频（NoSleep.js 的办法），iOS 播视频时不自动锁屏。两种都没生效才显示提示。
- **回到前台**：`visibilitychange` / `pageshow` 时立即发一包；WebSocket 已关就马上重连，没关就给 300 ms 证明自己活着；UDP 通道 600 ms 内没回音就重建。
- 手机页源码在 `pad/` 目录，由服务直接提供，CSS 和 JS 内联成一个 HTML，不经过游戏构建。纯函数（转向映射、滤波、协议校验、断流处理、连接统计）在 `pad/padcore.js`，手机页、服务、游戏和测试共用这一份。调试：手机页 `window.__pad`（`rtc.log` 是 UDP 通道最近的事件），游戏页 `window.__phonePad`（`figures()`、`rtcLog`）。
- **测试**：`npx vitest run tests/phonePad.test.ts tests/phoneServe.test.ts tests/phoneNet.test.ts`；端到端 `npx tsx scripts/phone-e2e.ts [--dir dist]`（无头，端口 5281 / 5284，截图输出到 `docs/screenshots/m4/phone/`；最后一段用 `DUSTMARK_FAKE_NET` 假装插上 / 拔掉 iPhone 数据线，检查配对面板）；弱网对照 `npx tsx scripts/phone-netsim.ts --root . --dir <构建目录> --variant dc`（端口 5282，代理 6283，模型见文件开头）。`DUSTMARK_FAKE_NET=<json>` 让服务用假的网卡列表（只给测试用），`DUSTMARK_CERT_DIR` 改证书目录。
